## Issues

### Tokens (TOK)

- **TOK-001 — High — Token conflict (primary vs warning)** — `source/collections/color-themes.json`: `primary/0…900` and `warning/0…900` both alias the exact same `orange/0…900` primitives in both Warm and Cool modes. Brand accent and warning state are the same color at every step; `border/Primary` (light `#A53800`) = `status/warning/fill` (light `#A53800`) = `chart/1`. `DUSQ_TOKEN_CHANGE_PROPOSAL.md:35` acknowledges warning must then be distinguished by "label/icon … not color alone", but nothing in the token layer enforces that.
- **TOK-002 — High — Token conflict (secondary vs error)** — `color-themes.json`: in the default Warm mode `secondary/*` aliases `red/*`, identical to `error/*`. `Background/Secondary/Default` resolves to `#BC0016` (light) / `#D72B33` (dark) — the same red as `status/error/fill` light `#BC0016`. A "secondary" filled button is visually indistinguishable from a destructive/error action. In Cool mode secondary flips to teal, so the secondary hue changes family between themes.
- **TOK-003 — Medium — Token duplication (tertiary vs informative)** — `color-themes.json`: `tertiary/*` and `informative/*` both alias `purple/*` in both modes — two names, identical values.
- **TOK-004 — High — Theme mode is a no-op** — `color-themes.json` Warm vs Cool: `primary`, `tertiary`, `base` (all 20 steps), `error`, `warning`, `informative`, `success` resolve identically in both modes; only `secondary` differs. `MAPPING.md:11,41` documents `data-temperature="cool"` as a theme switch, but neutral surfaces/text no longer change (the cool ladder was removed per `DUSQ_IMPLEMENTATION.md:7`).
- **TOK-005 — High — Contrast Control does not affect text/surfaces** — `source/collections/contrast-control.json`: every `onLight|onDark/Background/Neutral/*`, `Foreground/Neutral/*`, `Foreground/Primary|Secondary|Inverse/*`, `Background/Primary|Secondary/Default` and all `status/*/surface` values are identical across Standard / Medium / High (e.g. `onLight/Foreground/Neutral/Subtle` = `#564636` in all three). The "High contrast" mode only darkens borders/status fills/charts; body and subtle text contrast never increases.
- **TOK-006 — High — Inconsistent alias chain / orphan tokens** — `semantic-color-tokens.json` `Background/Primary/Default` aliases primitives directly (`neutral/900` Light / `neutral/0` Dark) while every other semantic role routes through Contrast Control. Consequently `Contrast Control: onLight/Background/Primary/Default` (`#A53800`) and `onDark/Background/Primary/Default` (`#CF6D13`) are referenced by nothing (orphans), and the primary CTA ignores the contrast modes entirely.
- **TOK-007 — High — Primary state family mismatch** — Semantic `Background/Primary/Default` is near-black `#1A1816` (Light) / off-white `#FAF8F5` (Dark), but its siblings `Background/Primary/Raised` = `#882700` / `#D1924F` (orange) and `Background/Primary/Subtle` = `#E7D5BE` / `#371300` (orange tints), and `border/Primary` = `#A53800` / `#D1924F`. Any consumer using Raised for hover/pressed or Subtle for tonal variants jumps from black to orange — the primary family is not one hue.
- **TOK-008 — Critical — Primary foreground vs primary background** — `Foreground/Primary/Default` resolves to `#371300` (Light) / `#FFF8F0` (Dark), while `Background/Primary/Default` resolves to `#1A1816` / `#FAF8F5`. Paired by name they give 1.06:1 (Light) and 1.01:1 (Dark) — effectively invisible text. Name-based pairing ("primary foreground on primary background") is the natural reading of this token set (verify actual component usage in steps 3–5).
- **TOK-009 — Medium — Duplicate chart series colors** — `semantic-color-tokens.json` `chart/1` and `chart/4` both resolve to `#A53800` (Light) / `#D1924F` (Dark) in every contrast mode; series 1 and 4 are indistinguishable. `chart/1/4` also equal `status/warning/fill` and `border/Primary`, and `chart/2` equals `status/error/fill`, so data series read as status signals.
- **TOK-010 — Medium — Low-contrast border tokens** — `border/subtle` Light `#B7AA9D` on `Background/Neutral/Default #FAF8F5` = 2.14:1 and on Page `#EBE7E4` = 1.85:1; Dark `#6D5946` on `#1A1816` = 2.67:1 and on `#111111` = 2.85:1. - **TOK-011 — Medium — Neutral ladder hue/step discontinuities** — `primitive-color-tokens.json`: `neutral/50…850` are warm brown (`#EBE7E4` … `#322821`), but `neutral/950` is pure grey `#111111` (no warm hue) and `neutral/900` `#1A1816` is a much larger luminance step from `850 #322821` than other steps. `neutral/0 #FAF8F5 → 50 #EBE7E4` is also a large jump.
